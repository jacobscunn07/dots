# CLAUDE.md

Global instructions for Claude Code, loaded in every project. Project-level
CLAUDE.md files are loaded alongside this one, not instead of it. Where the two
conflict, follow the more specific instruction.

## Environment

## Code style

- Never use an em dash (the "—" character). Use a plain hyphen (-) instead.
  This applies to everything you write: prose, code comments, commit messages,
  documentation, and replies in chat.
- Never hand-edit a file that is marked as auto-generated. If its contents are
  wrong, change the generator or its source input and regenerate. Check for the
  usual markers before editing: "DO NOT EDIT", "@generated", "Code generated by
  ... DO NOT EDIT", or a path that is plainly a build artifact or lockfile.

## Workflow

- Never add Claude as a co-author on a commit. No `Co-Authored-By: Claude`
  trailer and no "Generated with Claude Code" footer on commits or PR bodies,
  unless I explicitly ask for one.
- Hold the same bar for engineering excellence regardless of who caused the
  problem. If you hit a lint error, a failing test, or a flaky test, fix it,
  even when it predates your change or is unrelated to the task at hand. Do not
  skip it, silence it, mark it as expected-fail, or route around it. If a fix is
  genuinely out of scope, say so explicitly rather than leaving it unmentioned.
